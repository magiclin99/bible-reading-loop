# audit/ — 連結稽核

`links.tsv` 的 29378 個連結全部通過語料驗證（目標經節存在），但**那個「零失敗」
只證明目標存在，不證明指對了**。實作過程中抓到的 6 個承接錯誤全都「驗證通過」，
只是碰巧註標對不上才露餡 —— 若它們指向的節剛好有對應註標，就會靜默通過。

所以真實錯誤率無法用規則量測，只能靠語意判讀。

## 流程

```
python make_audit_packets.py      # → audit/packets/day-NNN.json（364 份）
（每天一個 sub agent 判讀）        # → audit/concerns.tsv
```

## packets/

每筆待驗連結備妥兩邊的脈絡，agent 不需自己翻資料：

| 欄位 | 內容 |
|---|---|
| `id` | `太1:1#1@12` — host 經節 + 註標 + body 位移 |
| `host` | 這條註解屬於哪一節 |
| `context` | 註解上下文，連結文字以【】標出。取整段而非固定字數窗，因為承接鏈要看得到 |
| `link_text` | 被連結的原文 |
| `target` | 目前指向的目標 |
| `target_text` | 目標那一節的經文內文 |

## concerns.tsv

agent 的產出是**待審清單，不是判決**。規則的產出仍是 ground truth：

- agent 只能舉手，不能改連結
- 每筆疑慮需附具體理由，最終由人裁決
- agent 本身也會誤判 —— 若一份清單充滿假警報，稽核就失去意義。
  故 agent 被要求「預設沒問題，只有能說出具體理由才回報」

## 已知的殘餘問題（規則層面，非 agent 發現）

| 情形 | 數量 | 狀態 |
|---|---|---|
| `該處` 後接的引用（如「與徒二46（見該處註2）和五42相符」的「五42」） | ~1 | 括號重設鏈，五42 會退回本卷 |
| 指向來源本身就缺的註標 | 2 | 已降級為純經節連結 |
